# Budget Extractor

Extracts tabular data from City of Pittsburgh 2026 budget PDFs (operating and capital) into structured CSVs, then powers an Astro-based web explorer for browsing department budgets, revenue, expenditures, and capital projects.

Key components:
- **Spatial table extractor** (`utils/spatial_table_extractor.py`) — core PDF-to-CSV engine using pdfplumber word positions
- **Workflows** (`workflows/`) — extraction pipelines (currently empty; all extraction is done via `utils/spatial_table_extractor.py`)
- **Scripts** (`scripts/`) — utilities for splitting PDFs, regression testing, building web data, extracting chart images, LLM-based content judging, and rendering page images
- **Web app** (`web/`) — Astro + Preact + Tailwind static site deployed to Netlify; visualizes extracted budget data with Observable Plot charts
- **Regression suite** — expected CSV baselines for 111 PDFs (47 operating + 64 capital) to catch extractor regressions

# Project Structure

- `input` directory contains the raw PDF files and section definitions
  - `sections-operating.json` and `sections-capital.json` define section boundaries
  - `split-pdf/operating/` and `split-pdf/capital/` contain per-section PDFs (gitignored, regenerate with `scripts/split_pdf.py`)
- `output` directory contains the extracted data
  - `output/regression/expected/operating/` and `output/regression/expected/capital/` contain test baselines
  - `output/glossary/` contains the extracted budget glossary JSON
  - Each workflow writes to `output/{workflow_name}/`
- `scripts` directory contains standalone utilities (split PDFs, regression tests, build web data, extract chart images, LLM judging)
- `workflows` directory contains the workflow modules
- `utils` directory contains the shared utilities
- `web` directory contains the Astro + Preact static site (budget explorer)
- `docs` directory contains project documentation (see below)


# Workflow Structure
Each workflow is a self-contained module that can be run independently of all other workflows.

These workflows may use shared utilities and dependencies, but they are not required to do so.
- Any shared utilities must be located in the `utils` directory.

All outputs of a workflow should be put in the `output` folder in a subfolder named after the workflow.

Each workflow is given a directory in the `workflows` directory. 
Workflow directories are named using snake_case, such as "extract_revenue_tables".
Each workflow directory contains a README.md file describing:
- The purpose of the workflow
- The input files required to run the workflow
- The output files generated by the workflow
- A high-level overview of the workflow
- Any dependencies required to run the workflow

# Spatial Table Extractor

The core utility is `utils/spatial_table_extractor.py`. It extracts borderless, whitespace-separated tables from Pittsburgh budget PDFs using pdfplumber word positions.

Key concepts:
- Words are clustered into rows by y-position, then columns are detected by finding consistent inter-word gaps across rows
- Dollar signs (`$`) and their whitespace placeholders mark column boundaries; these are detected before being stripped
- Sub-tables are split by horizontal rules, colored bands, and large vertical gaps
- Multi-line headers (e.g., "2025" / "Budget") are detected and merged into the following data table
- Column structure propagates from header-bearing tables to subsequent headerless tables with similar x-extent
- Page-level headers ("City of Pittsburgh...", "Fiscal Year 2026") are filtered before table detection
- False positives (prose blocks, single-cell tables) are filtered by column count and multi-column utilization ratio

# Regression Tests

Run `python3 scripts/test_regression.py` to verify extractor output against expected CSVs.

- Expected outputs live in `output/regression/expected/{budget_type}/{pdf_stem}/P{page}T{table}.csv`
- Debug outputs (regenerated during development) go to `output/regression/debug/{pdf_stem}/`
- To regenerate debug output for a PDF: `SpatialTableExtractor().render_debug('path/to/pdf', 'output/regression/debug')`
- After visually confirming debug CSVs are correct, copy them to `output/regression/expected/{budget_type}/` and re-run the regression test
- Always run regression tests after modifying the extractor to catch regressions across all PDFs

# Dev Container Constraints

This project runs in a devcontainer with limited memory. Follow these rules to avoid crashing it:

- **Never use `kill %1` or similar job-control kills.** Shell job numbers are unreliable across Bash tool invocations and may target the wrong process, potentially killing container-critical processes.
- **To kill a dev server, use `pkill -f`** with a specific command string (e.g., `pkill -f 'astro dev'`). This targets the right process by name.
- **Never run dev servers as background jobs** (`&`). Use `run_in_background` instead, which is managed properly.
- **Never spawn multiple dev server instances.** Always confirm the previous one is stopped before starting a new one.
- To start the web dev server: `cd web && npm run dev` (foreground, or with `run_in_background`)
