# Project Structure

- `input` directory contains the raw PDF files
- `output` directory contains the extracted data
- `workflows` directory contains the workflow modules
- `utils` directory contains the shared utilities


# Workflow Structure
Each workflow is a self-contained module that can be run independently of all other workflows.

These workflows may use shared utilities and dependencies, but they are not required to do so.
- Any shared utilities must be located in the `utils` directory.

All outputs of a workflow should be put in the `output` folder in a subfolder named after the workflow.

Each workflow is given a directory in the `workflows` directory. 
Workflow directories are named using snake_case, such as "extract_revenue_tables".
Each workflow directory contains a README.md file describing:
- The purpose of the workflow
- The input files required to run the workflow
- The output files generated by the workflow
- A high-level overview of the workflow
- Any dependencies required to run the workflow

# Coding Guidance

- In every subdirectory, create a small README.md file 2-3 sentences long that describes the content of the directory
- At the top of every Python file, add a docstring 1-2 sentences long that describes the purpose of the file
- Ensure that type hinting is used for all parameters, return values, and variables
- For CSV outputs with non-obvious columns, include a `DATA_DICTIONARY.md` describing column names, types, and valid values
