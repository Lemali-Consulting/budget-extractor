# Ball-Based Budget Visualization

**Date:** 2026-03-23
**Status:** completed

## Goal

Build an interactive "budget balls" visualization where each ball represents $100K of spending. Departments appear as color-coded clusters; clicking a department drills down into its expenditure categories, reusing the full color palette. Balls pour/cascade into view with a physics-style animation.

## Current State

The web app has 15+ chart components, all using Observable Plot for static/semi-interactive charts. There is no canvas-based or physics-driven visualization. The data pipeline already produces:
- `department-budgets.json` — 47 departments with totals per year (top-level data)
- `budget-data.json` — per-department `financial_summary` tables with 2-digit category → 5-digit subcategory hierarchy (drill-down data)

The 2026 operating budget is $772M across 47 departments = ~7,744 balls at $100K each.

## Data Pipeline

### New build script: generate drill-down JSON

The existing `department-budgets.json` works for the top level. For drill-down, we need a new view file extracted from `budget-data.json`'s `financial_summary` tables.

**New file: `web/src/data/views/department-expenditure-details.json`**
```json
[
  {
    "department": "Bureau of Police",
    "slug": "bureau-of-police",
    "total": 117958522,
    "categories": [
      {
        "code": "51",
        "name": "Personnel - Salaries & Wages",
        "amount": 94055583,
        "subcategories": [
          { "code": "51101", "name": "Regular", "amount": 72834621 },
          { "code": "51201", "name": "Longevity", "amount": 5100000 }
        ]
      }
    ]
  }
]
```

This is generated by a new step in `scripts/build_web_data.py` that parses `financial_summary` table rows, identifies 2-digit parent codes vs 5-digit subcodes, and extracts the 2026 Budget column value.

**Coverage:** ~29 departments have `financial_summary` tables. The remaining ~18 are trust funds and special accounts (tiny amounts). For departments without detail, the drill-down shows a single "Total" ball cluster.

## Proposed Approach

### Phase 1: Data prep + canvas scaffolding

1. **Add d3-force dependency** — `npm install d3-force d3-scale d3-ease` (only the modules needed, not all of d3)
2. **Add drill-down data generation** to `build_web_data.py` — parse `financial_summary` tables into the JSON format above
3. **Create `BudgetBalls.tsx`** — Preact component with a `<canvas>` element, basic resize handling via `useContainerWidth` pattern
4. **Create page** — `/visualizations/` index or `/visualizations/budget-balls/` route

### Phase 2: Top-level department view

5. **Color palette** — Define 12-15 distinct colors (enough for visual grouping; departments cycle through them). Small departments (<5 balls) get grouped into an "Other" cluster to reduce clutter — configurable threshold.
6. **Ball sizing** — Each ball = $100K, rounded up (min 1 ball per department). Responsive radius: ~4px desktop, ~6px tablet, ~8px mobile (fewer, larger balls on mobile could also use $500K per ball).
7. **Force simulation** — d3-force with:
   - `forceCenter` to keep the layout centered
   - `forceCollide` to prevent overlap (radius + padding)
   - `forceManyBody` with mild negative charge for spacing
   - Custom `forceCluster` to pull balls toward their department's centroid (standard d3-force pattern)
   - Department centroids arranged in a grid or packed circle layout, sorted by size
8. **Pour animation** — On load, balls spawn off-screen (top) with staggered delays per department (largest first). A temporary `forceY` pulls them downward, simulating a cascade. Once settled, this force is removed.
9. **Canvas rendering** — requestAnimationFrame loop during simulation; once `simulation.alpha() < 0.01`, stop the loop and render a final static frame. Re-render on hover/click.
10. **Hit detection** — On mousemove, find the ball whose center is closest to the cursor (within radius). Show a tooltip with department name + total. On click, trigger drill-down.
11. **Labels** — After balls settle, render department names as canvas text near each cluster's centroid. Only label clusters above a size threshold to avoid clutter.

### Phase 3: Drill-down view

12. **Transition out** — On department click, animate non-selected balls shrinking to zero (scale down + fade out over ~400ms). Selected department's balls remain.
13. **Recolor** — Reassign the full color palette to the department's expenditure categories (2-digit codes). Each ball gets its new color.
14. **Re-cluster** — Run a new force simulation grouping balls by category. Same pour/settle behavior but starting from current positions.
15. **Category labels** — Show category names (e.g., "Personnel", "Benefits", "Services") near each sub-cluster.
16. **Sub-drill-down (stretch)** — Clicking a category could further break into 5-digit subcategories. Same pattern. Limit to 2 levels for v1.
17. **Back button** — A visible "← All Departments" button (HTML overlay, not canvas) resets to the top-level view with a reverse animation.

### Phase 4: Polish + responsiveness

18. **Mobile adaptation** — Detect viewport width. Below 768px, use $500K per ball (~1,549 balls) with larger radii. Below 480px, consider $1M per ball (~774 balls).
19. **Legend** — Color legend showing department names (top level) or category names (drill-down). HTML overlay positioned beside or below the canvas.
20. **Accessibility** — Add an `aria-label` describing the visualization. Provide a "View as table" toggle that shows the same data in a standard HTML table (reuse existing table patterns).
21. **Performance** — Profile with 7,744 balls. d3-force with collision detection is O(n log n) per tick via quadtree; should be fine. Canvas drawArc for 8K circles is trivial. If cascade animation is sluggish, reduce ticks per frame or batch ball spawning.

### Phase 5: Navigation integration

22. **Add to nav** — Add a "Visualizations" section to the header dropdown, or nest under "Explore"
23. **Smoke test** — Add Playwright test that verifies the page loads, canvas renders, and a click interaction works

## Decisions

- **"Other" grouping**: Yes — group tiny departments (trust funds, <5 balls) into an "Other" cluster
- **Department layout**: Organic freeform circle packing (not grid)
- **Year scope**: 2026 Budget only for v1 (multi-year toggle is a future enhancement)
- **Budget scope**: Operating budget only for v1 (capital is a future enhancement)

## Risks

- **Department of Finance dominance**: At 1,978 balls (26% of total), Finance dwarfs everything. The visualization might feel lopsided. Mitigation: the drill-down makes it interesting ("where does all that money go?"), and the spatial layout can give Finance more space without it obscuring others.
- **Cascade performance on low-end devices**: 7,744 balls spawning with collision detection could stutter on older phones. Mitigation: mobile uses fewer, larger balls; also can reduce simulation iterations during cascade.
- **d3-force settling time**: Large simulations can take 300+ ticks to settle. May need to warm-start (run ticks silently) or tune alpha decay for faster convergence, then only animate the last phase.
