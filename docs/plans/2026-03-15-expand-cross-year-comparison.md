# Expand Cross-Year Comparison: Personnel, Capital, and Summary

**Date:** 2026-03-15
**Status:** completed

## Goal

Expand the `/cross-year/` page from a department-totals-only view into a tabbed deep-dive showing personnel changes, capital project diffs, and improved aggregate statistics — giving a complete picture of what council changed between the mayor's proposal and the adopted budget.

## Current State

The page at `/cross-year/` compares `2025-department-budgets.json` (proposed) against `department-budgets.json` (adopted), matching by department name on the "2025 Budget" year column. It shows 35 departments, 4 changed, +$20.2M net. It does not show the full +$25.7M / +143 FTE difference visible in the aggregate data, nor any personnel or capital detail.

## Proposed Approach

### Phase 1: Enhanced Summary and Department Tab

Add aggregate stats from `budget-changes.json` (both years) to show the full picture at the top of the page, before the department breakdown.

1. Import both `2025-budget-changes.json` and `budget-changes.json` in the Astro page
2. Add a headline summary section above the existing comparison:
   - Total budget: proposed vs adopted (with difference)
   - Total FTE: proposed vs adopted (with difference)
3. Add FTE column to the existing department table by cross-referencing `personnel-by-department.json` from both years (both have `totalFte2025` and `totalBudget2025` fields)

### Phase 2: Personnel Comparison Tab

Build a new `CrossYearPersonnel.tsx` component showing position-level differences.

4. Import `2025-personnel.json` and `personnel.json` in the Astro page
5. Match positions by `(department, title)` key
6. Compare `budget2025` and `fte2025` fields across documents
7. Show three sections:
   - **Changed positions**: matched by dept+title, with budget or FTE differences (filter out differences < $100 as noise)
   - **Positions added in adopted**: in 2026 doc only, with non-zero `budget2025` or `fte2025` (filter out $0-budget renames)
   - **Positions removed from proposed**: in 2025 doc only, with non-zero `budget2025` or `fte2025`
8. Summary cards: total positions compared, changed, added, removed, net FTE change, net budget change
9. Sortable table with department, title, proposed FTE, adopted FTE, proposed budget, adopted budget, differences
10. Department filter dropdown to focus on one department

### Phase 3: Capital Projects Tab

Build a new `CrossYearCapital.tsx` component showing project-level differences.

11. Import `2025-capital-projects.json` and `capital-projects.json`
12. Match by `title` (project name)
13. Show three sections:
    - **Projects in both**: with any metadata differences (functional area, department, project type)
    - **Projects only in proposed** (6): dropped or consolidated by council
    - **Projects only in adopted** (3): added by council
14. Note likely consolidations (e.g., two McArdle bridges → one McArdle Roadway)
15. If capital funding source data can be compared for matching projects, show funding changes

### Phase 4: Tab Navigation

16. Add a tab UI to the page with three tabs: **Budget** (existing department comparison), **Personnel** (phase 2), **Capital** (phase 3)
17. Use URL hash (`#budget`, `#personnel`, `#capital`) to persist active tab
18. Each tab loads its own component with `client:load` (or `client:visible` for non-default tabs to reduce initial JS)

### Phase 5: Deploy Pipeline Fix

19. Add `python3 scripts/build_web_data.py --year 2025 --output-prefix 2025` to the deploy command in CLAUDE.md

## Data Dependencies

All data is already generated by `build_web_data.py`. No new extraction or build steps needed beyond the existing `--year 2025 --output-prefix 2025` command.

| Component | 2025 doc data | 2026 doc data | Join field |
|-----------|--------------|--------------|------------|
| Budget (existing) | `2025-department-budgets.json` | `department-budgets.json` | `department` + `year === "2025 Budget"` |
| Budget (enhanced) | `2025-budget-changes.json` | `budget-changes.json` | Top-level totals |
| Personnel | `2025-personnel.json` | `personnel.json` | `(department, title)` → compare `budget2025`, `fte2025` |
| Personnel dept | `2025-personnel-by-department.json` | `personnel-by-department.json` | `department` → compare `totalFte2025`, `totalBudget2025` |
| Capital | `2025-capital-projects.json` | `capital-projects.json` | `title` |

## Open Questions

All resolved — see `docs/decisions/2026-03-15-cross-year-expansion-design.md`:

1. ~~Tab vs accordion vs separate pages?~~ **Tabs**, with `client:visible` for non-default tabs.
2. ~~Position reclassification detection?~~ **Normalize only** (strip `*`, trim, lowercase). Filter $0-budget from add/drop lists.
3. ~~Capital funding comparison?~~ **Project-level add/drop only**. Note consolidations, skip funding source comparison.

## Risks

- **Data volume**: 923 + 974 personnel records could make the page heavy. Mitigate with pagination or department filtering.
- **False positives in position matching**: Title normalization differences (asterisks, capitalization) could inflate add/drop counts. Mitigate by normalizing titles (strip `*`, trim whitespace) before matching.
- **Capital project renames vs real adds/drops**: Some "dropped" projects may just be renamed. Document known consolidations (McArdle) but don't try to auto-detect.
